# v0.1.0

2026-11-16。一般的なブラウザアプリの固定シナリオを、動的SQL / AOT、IndexedDB、オフライン同期、SQLite / LTXの受け渡しまで検証する最初のリリース。

## 公開するモジュール

- `mizchi/sqlike@0.1.0`: MoonBit製SQLiteサブセット。`Connection` / `Statement` / `Bind` / `Column` / `Value`、動的SQL、AOT、SQLiteページ出力。Litestreamには依存しない。
- `mizchi/litestream@0.1.0`: LTX v3、LZ4 / CRC64、SQLite Session codec、revision・適用可否・競合解決。DBドライバーには依存しない。

TypeScriptのadapter、ビルド時compiler、Drizzle統合、Node relay / DO / peerの例はリポジトリから利用する。ルートnpmパッケージはprivateなデモ・検証用とし、npmには公開しない。

## 主な機能

SQLikeはCRUD / UPSERT / RETURNING、index、基本trigger、FKとCASCADE、STRICT、RIGHT / FULL JOIN、CTE、集約と対応範囲のwindow / JSON / 日時関数を実装する。[対応表](../internal/status-and-improvement-plan.md)で制限と検証先を管理する。

[固定DDL＋prepared statement](../internal/predefined-binary.md)はビルド時にバイナリへ変換でき、実行用entryからSQLパーサとschemaのJSON復元を除外する。JSON / 日時 / window等は[機能プロファイル](../internal/sqlike-feature-profiles.md)で選択できる。JSランタイムは既定で[Oxc圧縮](../internal/minification.md)を適用し、後続のtree shakingと公開APIを維持する。

保存はメモリ内の行ストアとIndexedDB行ジャーナルを組み合わせる。COW行ページ・主キー索引の共有・変更列patchを使い、strict commitの確認後に変更を公開する。保存先は[契約とfactory](../internal/indexeddb-persistence.md)で交換できる。LSMは実験専用で、通常・lite・Workerの配信バンドルに含めない。

同期はSQLとSession binaryを扱い、適用可否・一意に適用できない競合の判断を[利用側policy](../internal/backend-contract.md)へ渡す。trigger / FKの副作用を含むbinaryでは、対応driverのmaterialized applyを明示的に使う。LTX生成・直接適用は本家Litestreamの復元で検証する。各adapterの能力は同一ではないため、対応経路は[受入プロファイル](../internal/release-acceptance.md)を参照。

[Drizzle adapter](../internal/drizzle.md)は任意entry。Drizzle ORM 0.45.4 / Kit 0.31.11で生成6本＋custom 2本のmigrationを検証する。

## 互換性と移行

SQLite全機能の互換性は未達。未対応を明示拒否し、受理した結果の値・型・順序と失敗時の原子性をnative SQLiteと比較する。[全機能監査](../internal/sqlite-feature-audit.md)は未達を可視化し続ける。ブラウザE2EはChromiumが対象で、Firefox / WebKit・モバイルの保証は含まない。

既存JSON画像は従来の `AotDatabase` / `MoonDatabase` で読む。新しい `DefinedDatabase` は独立した保存namespaceとschemaIdを使い、JSON画像の自動変換や異なるschemaId間の自動migrationは提供しない。DDLや機能検査の変更を反映するため、定義はこのリリースのcompilerで再生成する。schemaIdが変わる場合は、利用側でデータ移行を用意する。別schemaの保存を黙って読み替えない。

## 検証

0.1.0へのバージョン更新後、MoonBit JS / Wasm GC各53件、Node 298件、Chromium E2E 56件、型チェックとproduction buildを通した。566入力をNode / Chromiumの動的 / AOT × JS / Wasmの8経路で比較し、失敗はゼロ。出力監査は各経路で432 probe一致・270件の原子的拒否・値の不一致ゼロを確認し、未検証・未対応の全機能監査は未達のままとした。

両モジュールのZIPを展開した外部consumerでも、独立した公開APIをJS / Wasm GCで実行した。`just p0-measure` と `just p0-check` の構成コマンド（本家Litestream付き `just check`、`just differential-audit`、`scripts/check-p0.ts --record`）を通し、[完了証拠](../../measurements/p0-completion.json)へソース・成果物・計測のhashを保存した。主キー索引だけのJS実行コアはBrotli 83,039 B（81.09 KiB）、host / 保存adapter込みで87,180 B（85.14 KiB）。
