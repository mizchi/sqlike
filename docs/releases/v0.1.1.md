# v0.1.1

November 17, 2026. SQLike adds catalog-selected runtimes, compiled Drizzle queries, and more SQLite subset features. SQLike and Litestream retain separate packages and share this release version.

```sh
pnpm add @mizchi/sqlike@0.1.1
pnpm add @mizchi/litestream@0.1.1
```

MoonBit packages: `mizchi/sqlike@0.1.1` and `mizchi/litestream@0.1.1`. The root npm workspace remains private.

## Catalog-selected runtimes

Fixed schemas and named queries can select the required core functions, statements, JSON function families, JOIN, ordinary and recursive CTE, and compound SELECT implementations. Omitted implementations are rejected when a catalog is loaded, including expressions in unused branches and schema definitions.

Simple JSON construction can omit the SQL JSON parser, path handling, editors, patch and aggregates. Nested JSON values retain the subtype reparsing they need. Default builds retain all supported features.

`@mizchi/sqlike/compiler` now exports `analyzeCatalogRequirements()`. Building a specialized runtime still uses the repository's MoonBit build tool; generated engines can be injected through `@mizchi/sqlike/defined/core` or `@mizchi/sqlike/runtime`. The fixed schema, statement and persistence formats are unchanged.

See [catalog build instructions and measured sizes](https://github.com/mizchi/sqlike/blob/v0.1.1/docs/catalog-build.md). The README distinguishes browser distribution totals from engine-only catalog sizes.

## SQLite subset additions

- Core: DISTINCT comparisons, bitwise operators, GLOB, char, sign, LIKE ESCAPE, scalar min/max, NULL ordering, named SQL binds, hexadecimal and separated numeric literals, and FROM subqueries with distinct labels.
- Optional: index metadata through `schemaMetadata`, aggregate FILTER through `aggregateFilter`, and JSON arrows / array and object aggregates through `sqlJson`.
- Precompiled Drizzle queries: `@mizchi/sqlike/drizzle/compiler` and `@mizchi/sqlike/drizzle/prepared` keep Drizzle and the SQL parser out of the browser execution path.

JSON subtype propagation, escape preservation, Unicode handling and function argument limits now match additional native SQLite cases. JSON patch target parsing retains SQLite's error precedence for NULL patches.

## Compatibility and migration

Recompile fixed catalogs with the 0.1.1 compiler. A changed schema identity still requires an application-managed migration; stored databases are not silently reinterpreted. JSON VALUE arguments that may carry a subtype through scalar subqueries or min/max are explicitly rejected until their exact propagation can be represented.

SQLite support remains a subset. JSON aggregate windows, arbitrary extensions and several other SQLite features remain unsupported. Browser validation covers Chromium. LSM remains experimental and excluded from the default bundles. See [supported SQL](https://github.com/mizchi/sqlike/blob/v0.1.1/docs/sql.md) and [compatibility limits](https://github.com/mizchi/sqlike/blob/v0.1.1/docs/internal/status-and-improvement-plan.md).

## Verification

The release checks cover native SQLite differential results and atomic rejection, JS / Wasm GC, standalone npm and MoonBit archive consumers, Chromium IndexedDB and offline reopening, Drizzle migrations, and SQLite / LTX restoration with upstream Litestream. Registry consumers are checked after publication, including the new compiler and prepared Drizzle entries.

After the version update, MoonBit passed 53 tests on each target, Node passed 362 tests, and Chromium passed 58 tests. The differential audit covered 566 cases across eight execution paths with zero failing checks. The feature audit observed 454 matching probes and 248 atomic rejections per target, with no successful-output mismatches.

The full SQLite feature audit remains incomplete; passing the supported corpus is not a claim of universal SQLite equivalence.
