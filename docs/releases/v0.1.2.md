# v0.1.2

November 17, 2026. This patch release improves repeated AOT execution while retaining the public APIs, catalog formats and persistence formats introduced in 0.1.1. SQLike and Litestream remain separate packages and share the release version.

```sh
pnpm add @mizchi/sqlike@0.1.2
pnpm add @mizchi/litestream@0.1.2
```

MoonBit packages: `mizchi/sqlike@0.1.2` and `mizchi/litestream@0.1.2`. The root npm workspace remains private.

## Prepared execution

Fixed-schema UPDATEs and simple primary-key SELECTs now use a separate executable IR. Program loading resolves table and column slots, comparison affinity/collation, assignment targets, RETURNING metadata and primary-key access. Each execution reads current rows, bindings, indexes and connection state. Queries updating the same table share an immutable row layout.

Complex expressions retain the validated AST evaluator. JOINs, aggregates, CTEs, range-index planning, INSERT and DELETE retain their existing execution paths. The scalar value operations and key normalization are shared between prepared and general execution.

Existing valid JSON AOT catalogs, binary definitions and stored images remain supported. A changed schema still requires an application-managed migration. No new SQLite syntax or universal compatibility claim is introduced. Litestream has no replication-protocol change in this lockstep patch release.

## Measurements and validation

The repository records paired JS / Wasm GC comparisons for JSON AOT and binary defined runtimes, plus new catalog-selected execution baselines. Measurements include real-changing UPDATEs, expression RETURNING, primary-key hits/misses and constraint rejection. Native SQLite checks cover typed results and failed-write state. Browser distribution totals and engine-only catalog sizes remain separate in the READMEs.

In the paired 5,000-row browser fixture against released 0.1.1, median plain UPDATE time decreased by 36–40% and expression RETURNING by 56–67% across JSON/binary catalogs and JS/Wasm GC. Primary-key hit timings vary by runtime, with overlapping sample ranges. These results describe this fixture, not a general speed guarantee. The [paired report](https://github.com/mizchi/sqlike/blob/v0.1.2/measurements/release-0.1.2-performance.json) records all samples and artifact hashes.

The release gates cover MoonBit JS / Wasm GC, Node and type checks, native SQLite differential audits, Chromium IndexedDB/offline flows, independent npm and MoonBit archive consumers, and SQLite / LTX restoration with upstream Litestream. SQL fragments and HTML strings are checked as bind data; the browser test separately verifies text rendering through offline reload. Prepared statements do not replace output-context XSS defenses.

SQLite compatibility remains a tested subset. Unsupported and unverified features remain visible in the feature audit. LSM remains experimental and excluded from default bundles.

See the [prepared-plan design and measurements](https://github.com/mizchi/sqlike/blob/v0.1.2/docs/internal/prepared-execution-plan.md), [supported SQL](https://github.com/mizchi/sqlike/blob/v0.1.2/docs/sql.md), and [verification evidence](https://github.com/mizchi/sqlike/blob/v0.1.2/measurements/p0-completion.json).
