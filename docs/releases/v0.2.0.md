# v0.2.0

November 20, 2026. SQLike and Litestream use the same version on npm and Mooncakes. The root npm workspace remains private.

This release separates the default baseline engine from the full engine, adds SQL-file AOT generation for Vite, and makes optional execution/storage features independently selectable. It retains the tested catalog and persistence formats.

## Upgrade from 0.1.2

The default SQLike entry now includes CRUD, RETURNING, JOINs, aggregates, indexes, transactions, FK and STRICT. JSON, CTEs, triggers and windows require the full entry:

```diff
- import { openDatabase } from '@mizchi/sqlike';
+ import { openDatabase } from '@mizchi/sqlike/full';
```

MoonBit applications make the equivalent import change:

```diff
- "mizchi/sqlike"
+ "mizchi/sqlike/full"
```

Each MoonBit entry owns its connection and statement types; pass values within the same entry. Import one prebuilt engine per JS application to avoid duplicated runtime code. `@mizchi/sqlike/runtime`, `/aot/core` and `/defined/core` provide engine-free hosts for custom builds.

Valid existing JSON AOT catalogs, binary catalogs and saved images keep their formats. A specialized engine rejects catalogs requiring omitted features. Schema changes still require an application-managed migration. Recompile fixed catalogs when adopting newly supported syntax or capabilities.

Install both packages at the matching version:

```sh
pnpm add @mizchi/sqlike@0.2.0
pnpm add @mizchi/litestream@0.2.0
# MoonBit:
moon add mizchi/sqlike@0.2.0
moon add mizchi/litestream@0.2.0
```

## Vite AOT

`sqlikeAot` from `@mizchi/sqlike/vite` scans SQL files such as `src/client/**/*.sql`. It generates a catalog-selected JS engine, named-query types and size reports. Browser code imports `openDatabase` and `queries` from `@mizchi/sqlike/aot`.

The plugin handles SQL edits, additions and deletions in development/build watch. Mixing ordinary SQL or another prebuilt engine into the same AOT build fails with the offending import. Builds require Node.js 24+, Vite 8 and the MoonBit CLI; the browser receives the selected engine and catalog. [Vite guide](../vite-aot.md).

## Runtime and storage choices

- Portable AOT works on JS and Wasm GC. Public API selection can retain only four execute exports or add prepared handles, image APIs, transactions and deltas independently. Statement atomicity remains enabled.
- `/aot/native` provides JS-only typed bindings and positional results with reusable SELECT handles. Public handle ownership, reset and finalization remain explicit.
- The optional incremental SQLite pager supports replaceable memory/IndexedDB providers, atomic LTX checkpoints and outbox persistence. Structural changes retain the full-export fallback.
- Durable AOT adapters reuse binary logical row chunks, recover locally, retry verified outbox entries and defer checkpoints while the pending-file limit is reached.

[AOT APIs](../native-aot.md) · [Incremental pager](../incremental-pager.md).

## SQL and execution

New optional capabilities cover aggregate ORDER BY, row-value comparisons, UPDATE FROM, virtual generated columns and the supported subset of `json_each`/`json_tree`. Expression defaults, CREATE TABLE AS initialization, integer/string formatting and unambiguous single-MIN/MAX representatives expand the tested subset.

Dynamic SQL gains an opt-in bounded statement cache. Catalog runtimes reuse prepared execution metadata. Index/row cache changes reduce movement and redundant work. Query-shape pruning and compact readers reduce unused code; runtime size changes are measured separately from query speed.

Not every SQLite construct is supported. In particular, ambiguous aggregate outputs, unsupported format conversions, physical schema metadata and other documented gaps fail explicitly. Chromium is the validated browser; other browsers remain follow-up work. Query rows remain in memory even with IndexedDB persistence.

## Measurements and validation

The English/Japanese READMEs include refreshed engine sizes, browser distribution sizes and 5,000-row performance comparisons. The 100,000-row chart and focused optimization experiments retain their historical dates. Reports identify engine/host/catalog scope, compiler settings and source/artifact hashes. Reader microbenchmarks include slower Wasm means and do not establish a speed improvement.

Release preparation validates MoonBit JS/Wasm, Node and type contracts, Chromium IndexedDB/offline flows, native SQLite differential audits, independent npm/Mooncakes archive consumers and upstream Litestream restoration. Passing sampled outputs does not establish universal SQLite compatibility.

Publication, OIDC provenance, registry downloads and fresh Linux CI must be checked against the final committed release source. The [preparation record](../internal/release-0.2.0-preparation.md) tracks the actual completed checks separately from these publication steps.

Follow-up enhancements: [schema pruning #7](https://github.com/mizchi/sqlike/issues/7), [binary initialization and typed ABI #8](https://github.com/mizchi/sqlike/issues/8), and [query-shaped optimizer selection #9](https://github.com/mizchi/sqlike/issues/9).
